# Identity claim lifetime enrollment v1

The required JWT claims in spec §5.1 remain `userId`, `jti`, `exp`, `iss`, `aud`; `iat` is optional under an issuer issuance contract. The verifier's deployment policy defaults to `REQUIRE_IAT`, preserving existing enrolled deployments and the original eight-argument `IdentitySecurityContract` constructor.

The typed `IdentitySecurityContract.claimLifetimePolicy` has version `1`, mode `REQUIRE_IAT` or `OPTIONAL_IAT_ATTESTED_LIFETIME`, and `issuerAttestationReference`. Optional mode requires a concrete non-placeholder enrollment reference identifying the reviewed issuer contract that guarantees every issued token's total lifetime is at most this enrollment's finite positive `maximumJwtLifetime`. The reference is trusted deployment input, not evidence extracted from a JWT or a substitute for the external issuer approval. Do not enable it without that approval. The contract is specific to the configured issuer/audience and applies to the real gateway/bootstrap/native RS256 verifier.

Mounted local enrollment reads this typed policy from the identity object. Older mounted documents with no policy field receive the strict legacy default; explicit null, invalid mode/version or optional mode without a concrete attestation reference fail startup. Local mounts remain `LOCAL_TEST_ONLY`, not a production issuer attestation. The deployment template remains `REQUIRED_UNCONFIGURED` and retains unresolved issuer/audience, lifetime, jti-refresh, revocation and calling policy inputs.

When `iat` exists, its type, lifetime (`exp > iat`, `exp-iat <= maximumJwtLifetime`), future issue time and expiry checks are unchanged. `iat:null` or a malformed claim fails rather than being treated as absence. When absent under the optional enrolled mode, the verifier requires `exp <= now + maximumJwtLifetime + clockSkew` and checks expiration/`nbf` normally. This bounds remaining validity; total issuance lifetime is guaranteed by the issuer contract and cannot be reconstructed from `exp`. `AuthPrincipal.issuedAt()` is then null, and `knownIssuedAt()` is empty. The verifier never fabricates an issuance timestamp. Current production source has no consumer of that principal issuance timestamp; future consumers must use the explicit unknown state.

Concrete issuer approval, accepted lifetime, reference and required production security configuration remain external inputs. This implementation does not declare the identity platform enrolled or Task 3 acceptance complete.
