# Native resource, retirement and database provider contract

Status on 2026-10-11: **source implemented; production NOT_QUALIFIED**. This inventory describes the resolved property contract and native constructor limits. It records no throughput, latency, oldest-row-age, failover, archive or restore acceptance result. Tests and deployments were not run for this work.

`ENFORCED` means a source check or reservation exists. `FIXED` means a native constant independently controls the path. `INPUT` means an explicit enrollment supplies the value; there is no qualified production value in this change. All rows remain **NOT_QUALIFIED** for production capacity. A configured ceiling does not establish that its maximum fits the proposed pod envelope.

## Database admission and transaction contract

[DbResourceProfile](../../signaling-storage/src/main/java/io/webrtc/signaling/storage/DbResourceProfile.java) and [DbCost](../../signaling-storage/src/main/java/io/webrtc/signaling/storage/DbCost.java) make per-class count, retained bytes, result bytes, completion slots and declared service floor explicit. [DbAdmission](../../signaling-storage/src/main/java/io/webrtc/signaling/storage/DbAdmission.java) reserves these dimensions atomically before completion allocation and virtual-thread dispatch. Credits are nonborrowable by class. Saturation, unsupported cost or insufficient original remaining deadline rejects before dispatch. The service number is a **declared profile**, never a throughput measurement by this implementation.

Native [database enrollment](../../signaling-app/src/main/java/io/webrtc/signaling/app/runtime/NativeControlDatabaseEnrollment.java) carries `resourceProfiles`; [resources](../../signaling-app/src/main/java/io/webrtc/signaling/app/runtime/NativeControlDatabaseResources.java) constructs admission from those profiles. Every production actor/control boundary, including an actor-supplied boundary, must pass `requireProductionProfiles` at [startup](../../signaling-app/src/main/java/io/webrtc/signaling/app/NativeRuntimeStartup.java). A positive service floor and an evidence reference are required. The reference is an operator obligation to furnish and verify actual evidence, not an in-process proof of qualification. Missing profiles/provider contract fails startup.

Compatibility constructors deliberately produce `LOCAL_TEST_ONLY` profiles: input2MiB, result32MiB for RECOVERY/MAINTENANCE and4MiB for other classes, retained charge `2×input + 2×result`, class byte totals=count×charge, completion slots=count, service floor0. These large finite ceilings preserve legitimate outbox128 payloads of8KiB plus base64 expansion, destinations and immutable object overhead; a blanket1MiB result limit would reject valid jobs. They are not production recommendations. The mounted legacy profile default exists only inside the acknowledged `local-minikube`/`LOCAL_TEST_ONLY` parser; production cannot authorize provider fencing from this acknowledgement.

Opaque `Callable` closures have no introspectable captured-size contract. The compatibility submit methods charge the profile maximum; that is reservation accounting, **not a hard bound on arbitrary captured objects or JDBC temporary allocations**. Typed `boundedCharge` callers declare actual upstream input/result bounds, validated against the profile (retained charge `2×input + 2×result`). Retirement uses source-bounded key projections and that typed API. Other generic callers still rely on their existing protocol/schema/input checks and must be audited before a production profile is accepted. Full process heap, direct buffers, driver/JPA state, completion callback retention and aggregate connection overhead need separate evidence.

## Fair finite retirement

The native scheduler invokes `RetentionWorker.pruneDue(512, originalBudget)` every100ms. It no longer visits16,384 mostly-empty buckets one at a time (the old nominal full cycle took1,638s). Indexed hints use stable full keys and a sampled primary-clock upper horizon. Independent cursors/per-kind quotas cover final command results, terminal calls, terminal homes, expired outbox rows (including quarantined rows), and published transfer staging. Hints are discovery only.

Selection consumes a contiguous prefix of each kind in round-robin order, at most16 distinct buckets. Cursors advance only through consumed hints; dropped suffixes remain eligible next time. Per-kind horizon exhaustion wraps. Frozen/busy prefixes still advance; bucket transaction order rotates each invocation so a deadline cannot always exclude the same suffix. Groups are sorted for deterministic authority work; each transaction acquires cell100 then its one bucket101 before fresh exact row deletion. There is no multi-bucket partial lock set. Every fresh delete rechecks exact full key, bucket, authority, expiry and eligibility using `FOR UPDATE SKIP LOCKED` and `(tableoid,ctid)` matching across partitions. Fenced/busy bucket rollback is a skip; other failures and UNKNOWN propagate with physical accounting retained.

Discovery allocates≤64 hints per kind and≤15 call hints. Conservative call reservation includes the parent plus16 possible workflow children; the worst discovery page is≤511 touched rows, within DB11's512 limit. Exact retirement counts children and their key projection bytes before deletion while the parent lock prevents concurrent FK child insertion. Per-transaction key/projection accounting is≤1MiB. Public `Report` counts deleted parent rows; it must not be interpreted as aggregate child count. The128 limit belongs to DB09 outbox claim/hint batches, **not** retirement. `prune(bucket,limit)` remains source-compatible and validates its≤512 input.

[V015](../../signaling-storage/src/main/resources/db/migration/V015__fair_retirement_access_paths.sql) adds command/call bucket retirement indexes, global outbox expiry and published transfer due indexes. It uses existing V002 global final/terminal expiry, V008 home bucket expiry and V013 outbox bucket expiry paths. Old migrations are unchanged. Index presence alone does not prove planner choice, bounded lock wait, vacuum cost, oldest age or steady-state storage at arrival rate; those gates remain NOT_RUN.

Published transfer cleanup preserves the existing `WorkerFence.cleanupBucket` source-FROZEN exception: exact current transfer ID plus published receipt is required. Generic FROZEN rows cannot be retired. Transfer receipts, barrier authority and worker fences were not weakened. Oversized/invalid legacy copy keys stay retained and require owner-led remediation.

### Opaque tombstones and privacy

Permanent issuer+jti→user binding, absorbing gateway boot death, guard/high-water tokens and replay fences are retained. This change adds no generic session, user guard, dead boot or opaque security tombstone deletion. The complete issuer lifetime, maximum stale-message/dedup/re-registration horizons and identity attestation needed to prove safe retirement are still missing; steady-state size for these families remains NOT_QUALIFIED. Raw identity/data privacy detachment must preserve the opaque fence/key needed to reject stale registration and replay. The existing enrolled privacy detachment owner/key remains required; a deadline or row age by itself is not deletion authority. Refer to the [claim lifetime policy](identity-claim-lifetime-policy.md) for the separate issuer input contract.
