# Native initial ICE application receipt v1

Additive, opt-in capability: `native-initial-ice-receipt-v1`. Initial ICE repair cannot depend on a post-DTLS data channel. Public operation `INITIAL_ICE_RECEIPT` uses existing authenticated WSS command, native RELAY RPC and boot-bound gateway delivery. It is volatile, never a durable command or critical commit. Existing protobuf envelopes retain their field numbers; the new operation uses the existing type/payload fields with schema_minor=1. An old binary must never receive the new operation while the fleet capability is closed.

AUTH/AUTH_REFRESH may opt in with payload `initialIceReceiptsV1:true`; AUTH_OK echoes the boolean only if this gateway boot and native fleet advertise the capability. Default clients omit the field. ICE_CANDIDATES and END_OF_CANDIDATES may then add `receiptProtocol:"native-initial-ice-receipt-v1"`. The marker is part of the original authenticated immutable intent and declares sender support for this exact scope. A recipient emits receipts only if its own AUTH negotiation succeeded and the current incoming ICE scope carries that marker. Unsupported recipients omit receipts and use existing bounded gap/RESYNC behavior. Gateway ingress rejects receipt traffic without the channel's own negotiated capability; native relay and gateway egress independently check current authenticated fleet/boot capabilities.

Receipt top-level fields: v=1, type=INITIAL_ICE_RECEIPT, original requestId UUID, current routed callId, negotiationId and iceGeneration positive signed64 decimal strings. Payload: receiptVersion=1, senderSessionIncarnation UUID of the peer whose candidates were consumed, highestContiguous nonnegative signed64 decimal string, missingRanges list of at most32 ordered nonoverlapping pairs of positive decimal strings strictly above the cursor, endReceived boolean. Payload <=8192 bytes. Each native hop binds authenticated receipt sender, both ACTIVE home proofs, current coordinator/activation/round, actual recipient route and target peer incarnation. The peer verifies delivery route and scope before processing. No receipt authorizes a call/round mutation.

highestContiguous advances only after successful ordered addIceCandidate. endReceived means successful addIceCandidate(null), never END frame arrival or gateway queue/write completion. Missing-range requests select original cached ICE envelopes, with identical UUID, sequence and canonical payload. Native receipt UUID/encoding is reused when the receipt contents are unchanged. Browser retains at most32 cached receipt states and applies a100ms resend throttle; sender cache remains256candidates/256KiB/10s, receiver gap deadline10s. Reordered/stale cursors are ignored without regressing acknowledged progress. Invalid/future cursor/end proof causes RESYNC. No JWT/SDP/ICE/receipt is persisted. A timed-out physical PC operation remains fenced.

Interop, real browsers, initial ICE loss/reordering and production capability rollout are unrun gates. Enrolled external clients must implement this exact revision before enabling it.
