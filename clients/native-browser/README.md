# Native browser adapter 1.0.0

This ES2022 module implements the native public WSS `v:1` contract in this repository. Import `NativeBrowserClient` from `native-client.mjs` or the pinned package `@webrtc-signaling/native-browser` version `1.0.0`. It owns one active call and an injected real `RTCPeerConnection`. It has no HTTP fixture and stores no SDP/ICE in localStorage, IndexedDB or a durable journal.

```javascript
import { NativeBrowserClient } from './native-client.mjs';

const client = new NativeBrowserClient({
  peerConnection: pc,
  authorityDomain: trustedEnrollment.authorityDomain,
  handleControlEvent: async event => app.applyNativeControlEvent(event),
  onMessage: frame => app.applyNativeReply(frame),
  onResyncRequired: advice => app.startAuthoritativeResync(advice),
  onResetPeerConnection: snapshot => app.applyExplicitResetAdvice(snapshot)
});
const ws = new WebSocket(enrolledGatewayWssUrl);
client.attachWebSocket(ws);
ws.addEventListener('open', () => client.authenticate(userServiceJwt));
// After AUTH_OK, independently authorized native rebind/read must finish first.
client.command('RESUME', callId);
client.command('SYNC_CALL', callId);
```

The application supplies the real enrolled WSS URL, origin policy, existing identity token and its authoritative control-event handler. Never put the token in a URL. `handleControlEvent` must resolve only after the application has accepted the event. The adapter then sends exactly `{v:1,type:"EVENT_RECEIVED",requestId,callId,payload:{eventId}}` on that same authenticated socket. Gateway receipt tracking resolves the issued event version and full route internally; `EVENT_RECEIPT` is an application receipt response, with `ackCommitted:false`. A successful `WebSocket.send` is only queued transport work.

`ACK_COMMITTED` with `ackCommitted:true` marks a command committed. `COMMAND_RESULT` is a read or pending outcome. Unknown/error commands retain their original UUID and payload in the bounded pending map. Admission captures an immutable JSON copy and the exact encoded envelope; `retryCommand(requestId)` sends that captured encoding even if the caller subsequently changes its input object. Use `lookupCommandResult(originalRequestId)` for a native `GET_COMMAND_RESULT` read: it sends the original UUID with the original call scope (or no callId for INVITE) and an empty payload. It never overwrites the original retry intent. Calling `command('GET_COMMAND_RESULT', ...)` is unsupported. Replies correlate to the original pending entry; a read remains distinct from a committed acknowledgment. Release resolved entries with `releaseCommand`. The map caps at 256 commands and 256KiB; unresolved work fails admission when full. A reconnect requires new issued event receipts and discards prior route receipt commands. Optional durable application commands are described below.

Native `CALL_SNAPSHOT` establishes the call, round, generation and sender incarnation. The application must obtain a new authorized `SYNC_CALL` after a negotiation transition; relay frames never authorize a new round by themselves. Relay `sender.incarnation.value` is the actual Jackson `AuthenticatedSession` shape. Stale receiver route fields and remembered abandoned scopes are ignored; an unrecognized call/round/generation/sender triggers resync. Repeated snapshots of the same active scope preserve its cursor and dedupe state. Snapshot `resetPeerConnection:false` preserves the injected PC and healthy media. Attaching another WSS socket clears volatile signaling scopes, does not close/reset the PC, and requires native rebind/read again. An abandoned scope cannot restart at sequence 1: the next snapshot requires a fresh negotiated scope before more ICE signaling. Existing healthy media survives while the application resolves that advice. The adapter never interprets a transport reconnection as media failure.

The required immutable `authorityDomain` constructor input identifies the enrolled storage/authority epoch domain in which call versions are comparable. It must come from trusted application deployment/bootstrap enrollment; native public snapshots do not emit a storage epoch, and the adapter does not invent one or infer it from a socket URL. Within `(authorityDomain, callId)`, a bounded high-water map ignores lower-version snapshots before scope/reset/terminal changes or UI publication. Versions are never compared across call IDs or domains. The map allows 256 call/domain entries and fails admission instead of evicting ordering evidence. A change to the enrolled authority domain requires a new adapter instance; a healthy PC may still be supplied to that instance. Providing and validating this external enrollment value remains a production integration requirement.

ICE decimal64 fields use `BigInt`, with canonical decimal strings and maximum `9223372036854775807`. A batch has at most 20 candidates, 8KiB payload and 2KiB candidate text. The aggregate receiver window has at most 256 candidates and 256KiB, with a 10 second missing-sequence/remote-description deadline. `addIceCandidate` calls are awaited in contiguous sender order; duplicates below the cursor are dropped. An early terminal marker waits for every candidate through its terminal sequence, then calls `addIceCandidate(null)` once. Anything above that terminal, a conflicting buffered sequence, or an expired gap requires resync. Application/ICE async calls also have a 10 second completion bound. Browser promises cannot be cancelled; an ambiguous ICE operation blocks that PC's future signaling until the application supplies a different PC with `replacePeerConnection`. This exceptional fence is distinct from normal reconnect/media preservation.

A receiver scope is description-ready only after that exact scope's native OFFER/ANSWER successfully completes `setRemoteDescription`. Existing `pc.remoteDescription` from an older generation cannot authorize draining new ICE. One volatile record per scope retains the description's original UUID/type/content (at most 64KiB SDP). An exact duplicate is dropped without calling the PC again; conflicting identity/content requires resync before touching the ICE agent. Scope replacement clears description readiness and this record together with the receive window.

Reset/resync hooks accept synchronous or async application operations. They run under separate 10 second supervision so a callback can request native replies without blocking the WSS receive queue. `recoveryStates.get('reset'|'resync')` exposes PENDING/COMPLETED/FAILED and `recoveryCompletion` is the latest supervised completion promise. Hook exceptions/rejections/timeouts become FAILED state and do not recursively invoke recovery or produce unhandled rejections. At most one original physical operation per hook is admitted; after a timeout, admission remains occupied until that underlying operation settles. A wrapper timeout does not cancel application work. Recovery success/failure handling and an ultimately hung operation remain application responsibilities.

Use `sendDescription('OFFER'|'ANSWER', pc.localDescription.sdp)`, `sendIceCandidates(candidates)` and `sendEndOfCandidates()` for native WSS sending. The application wires its real `icecandidate` callback to those methods only after establishing the authoritative round; it owns local offer/answer creation. The adapter retains original native request IDs and sequence ranges in a volatile resend cache (256 candidates, 256KiB, 10 seconds). If a socket failure throws after admission, the error carries `requestId`; `retryIce(requestId)` sends the same original envelope. Socket-write ACKs never retire cache entries as application delivered. Without a negotiated receipt channel, cache expiry simply removes expired volatile material; a receiver gap independently requires resync, and there is no application delivery proof.

Optional pre-DTLS receipts use the capability `native-initial-ice-receipt-v1`. Set constructor `initialIceReceipts:true`; AUTH/AUTH_REFRESH requests `initialIceReceiptsV1`, and only an enabled AUTH_OK permits marking outgoing ICE with `receiptProtocol`. An opted-in receiver returns bounded native `INITIAL_ICE_RECEIPT` after actual ordered `addIceCandidate`, including the terminal null candidate. The server revalidates both ACTIVE homes, exact call/round/generation, peer incarnation, destination route and enrolled server feature. Both server build enrollment and matching clients are required; older peers retain the fallback. See [wire contract](../../docs/superpowers/execution/2026-10-12-pending-native-integrations/initial-ice-receipt-v1.md).

The existing authenticated ordered `RTCDataChannel` protocol `webrtc-signaling-ice-receipts.v1` remains available through `bindIceReceiptChannel(channel, remoteScope)`. It requires the application's trusted peer/DTLS binding and becomes available after connectivity. Native receipts let matching peers repair initial ICE before that channel exists. Both paths retain original envelope UUIDs, enforce bounded volatile caches, and retire material only from actual peer receipt. No receipt, SDP or candidate is written to the durable command journal. Initial native receipt state expires after 10 seconds; once peer capability is observed, unresolved cache expiry requires resync. Missing capability never implies peer delivery.

External inputs remain required: client repositories/package pins, trusted principal/domain enrollment, bootstrap/routing/tokens, origin/WSS enrollment, real PC and UI hooks, operator server capability enrollment, and matching-peer interop evidence. No browser, WSS, gRPC or mobile runtime execution has been claimed.


The explicit durable API uses `new DurableCommandJournal()` from `durable-command-journal.mjs`, passed as `journal` with trusted `principal: {issuer, jti, userId}` to the client constructor. `await client.persistCommand(type, callId, payload, originalRequestId)` commits the exact encoded intent before any socket send. `await client.restoreCommands()` restores only commands belonging to that exact issuer/jti/user and immutable enrolled authority domain, returns their original IDs, and sends nothing. Reconcile each with `lookupCommandResult(id)` and explicitly retry with `retryCommand(id)` under the same authenticated principal. The application must validate token identity against enrollment; never derive enrollment by decoding an unverified JWT or replace jti during token/session/account changes. A new principal cannot replay the previous principal's commands. Authentication tokens and proof material are never journaled.

One IndexedDB read/write transaction enforces at most 256 unresolved commands and 256KiB of serialized records globally across tabs, principals and domains. Unresolved records are never evicted. Allowed durable commands are INVITE (targetUserId only), ACCEPT, CANCEL, HANGUP, REJECT, DECLINE_ALL, and NEGOTIATE_REQUEST (iceRestart only); all other payload properties fail admission. SDP, ICE, media/quality data, tokens and proofs are excluded. Only an original route-correlated native ACK_COMMITTED/COMMAND_RESULT containing status FINAL settles the original record; PENDING, unknown/error, absent result, snapshot, application/transport receipt do not. Durable records cannot be released from memory until settlement completes. IndexedDB availability/quota/transaction failures fail admission; a send failure after persistence carries the original requestId. Browser storage durability and authenticated identity enrollment remain runtime integration requirements.

Pass `mediaRecovery: {createRestartOffer, onRecoveryState}` to opt into real PC connectionstatechange/iceconnectionstatechange handling. The controller fences observations to the injected current PC and authoritative sender scope. It sends native scoped MEDIA_CONNECTED, MEDIA_DISCONNECTED, MEDIA_FAILED, ICE_RESTARTING and MEDIA_RECOVERED with the current round/generation and monotonically increasing senderSequence. `observeMedia(type, payload, requestId)` is also available for explicit application observations; only senderSequence/quality and MEDIA_FAILED reason are accepted, matching ProtocolValidator. Quality contains the four nonnegative integer rttMillis/jitterMicros/packetsLost/framesDropped fields.

A disconnect starts the native 30 second recovery episode and waits 5 seconds before one original NEGOTIATE_REQUEST UUID; a failed PC admits the request immediately. Unknown transport outcomes retain that original ID for manual lookup/retry. Definitive MEDIA_DEBOUNCE consumes the UUID and never schedules a replacement. An original FINAL NEGOTIATION_GRANTED result triggers SYNC_CALL. Only a snapshot at or after the grant version with a fresh round/generation, OFFER_GRANTED, and this authenticated route as offerer permits the offer callback. `createRestartOffer({peerConnection, scope, iceRestart:true})` must perform actual `createOffer({iceRestart:true})` and `setLocalDescription`, returning `{sdp}`; the adapter sends the resulting OFFER only while the PC/episode/scope is still current. The real application wires answer creation and its ICE callbacks as above. The adapter never calls restartIce on a WSS change.

Offer and UI callbacks have 10 second supervision; the original physical promise continues to own admission until it settles. Offer timeout/failure blocks the ambiguous PC, and late completion cannot send an offer in a later scope. UI failure/timeout is supervised without inventing cancellation. The 30 second bound reports RECOVERY_EXHAUSTED through the native current scope; server authority remains the final recovery deadline/attempt decision. No browser runtime, IndexedDB cross-tab, media or WSS acceptance execution is claimed.

Durable admission validates primitive payload values before storage: targetUserId must satisfy native bounded identifier rules and iceRestart must be boolean. Arrays, nested values, absent required values, invalid v/UUID/call scope or extra envelope fields are rejected before the IndexedDB transaction. Recovery episodes are retired on unrelated PC/call/round/sender changes; only their own original grant's exact version and next round/generation can extend the episode. Late snapshots at another version require application reconciliation rather than inferring which request authorized the transition.
