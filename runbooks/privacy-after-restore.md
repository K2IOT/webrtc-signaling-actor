# Privacy and security after restore

Keep `RECOVERING`/readiness false until the current authoritative deletion and security journals are replayed. A backup can contain data detached after its snapshot, so a completed deletion row in the restored database does not certify current privacy state.

1. Authenticate the approved external deletion source; obtain original deletion IDs, keyed opaque subjects and high-water from outside the backup. Use the originally enrolled HMAC key/version and rotation/retention policy; a new random key cannot identify old subjects. Do not write raw JWT/subject/email/SDP/ICE to restore logs or evidence.
2. Reimport every relevant deletion request since the backup point, including requests the backup says were completed. Run bounded `PrivacyDeletionWorker` detachment operations through actual physical cleanup. Reapply optional-data/export/backup deletion policy. Retain minimum native fencing, session, winner, replay and tombstone identifiers through their published safety windows; deleting authority to claim privacy completion can resurrect stale work.
3. Catch up the authenticated ordered revocation/key-retirement source to its current high-water; use original ordered event IDs. Historical duplicate pages must not refresh security freshness. Confirm current native security progress and configured hard safety bound; absence of records is not an allow decision.
4. The enrolled replay verifier supplies a completion proof bound to cell, new storage epoch, recovery UUID, security and privacy high-waters and <=5s expiry. Native reactivation checks exact security cursor/freshness and zero unfinished deletion requests. The external verifier must prove all current detachments/replays, including journals absent from the restored snapshot; a local boolean or empty table is insufficient.
5. Retain signed opaque replay receipts, native completion timestamps and approved retention/backup policy. Do not reopen business traffic while the current source, HMAC rotation mapping, privacy policy or physical detachment is unavailable. Validate this with a real approved backup/restore drill before release.
