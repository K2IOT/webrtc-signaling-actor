# Candidate deployment contract

Status: **NOT_QUALIFIED**. Render validation checks Kubernetes object semantics; it does not demonstrate failover, three-AZ capacity, PKI enrollment or application readiness.

Run `PATH=/workspace/.onboarding/bin:$PATH bash qualification/scenarios/deployment-contract.sh` with Helm 3.19.0 and Python/PyYAML. The fixture contains reserved documentation addresses and a TEST_ONLY digest; never deploy it. Helm rejects missing production image, issuer, audience, secret, fingerprint and explicit network routes. Independently scale gateways while keeping the actor ingress-producer contract at six members plus one surge. The proposed 4Gi/2CPU app and 16Gi/4CPU database envelope requires measured capacity qualification; changing JVM memory without matching native/direct/socket limits requires requalification.

Use one namespace per cell, with a separate directory namespace. Supply the private Kubernetes API endpoint CIDR, authority endpoints, approved platform source endpoints, private actor peer endpoints, edge and monitoring namespaces. Service endpoints must route to the native **writer**, never a replica. CNPG operator uses namespace `cnpg-system`. Install official CloudNativePG **1.27.0** CRDs and controller, replacing its controller image with the exact amd64 digest in `config/compatibility-manifest.yaml`; verify the running deployment image before creating clusters. Both database manifests explicitly select amd64. Other architectures require digest and compatibility qualification.

Create external credentials, server/client CAs and workload-specific certificates before applying a cluster. App secret includes `runtime.yaml`, TLS private keys/certificates, `remoting.p12`, `trust.p12` and the three remoting password keys referenced by the chart. Mounting a secret is not evidence that its contents or trust roots are valid. No example JWT issuer, permissive peer policy or public remoting address is supplied. The actor discovery service is `signaling-<cell>` and selects the exact `app/plane/cell` labels required by `ShardingBootstrap.validateProduction`. Management is private mutual TLS; remoting uses TLS on port **25520**, matching the existing runtime. The health endpoint is private on 8559; business WSS/RPC is 8443. CNI must permit kubelet probes using its documented host-probe rules; test this in the target cluster. Cloud provider control of namespace labels, CIDRs and CNI enforcement is part of qualification.

Apply `deploy/directory/networkpolicy.yaml` in the dedicated directory namespace and enroll only authorized control-plane namespaces using the `signaling.directory-client=true` label. Cell authority networking is included in the chart. These policies permit CNPG peer replication and operator instance-manager access, with default-deny application networking. Backup transport requires an explicitly reviewed additional policy; no unrestricted backup egress is enabled.

CNPG synchronous configuration requires one eligible standby **in another AZ**, `synchronous_commit=on`, and `dataDurability=required`. Missing synchronous replicas blocks critical commits. Three instances have required zone anti-affinity. Initial authority/schema creation and role grants are controlled migration jobs using Task 1–8 scripts; normal app startup never creates authority epochs or runs destructive schema recovery automatically.

The annotations and supervised switchover settings express requirements, **not proof of physical fencing**. CNPG alone is not a hardware fencing attestation. Before authority admission after a writer change, require authenticated fresh fencing evidence for the old writer, matching cluster identity/storage epoch/new writer timeline, and verify that the promoted writer contains every acknowledged WAL record. The runtime must keep admission closed when these proofs, security freshness, clock bounds or synchronous durability are unavailable. Run the failover and recovery runbooks and retain their raw external evidence before release. Never reopen traffic from a soft process annotation, a DNS change or `pg_is_in_recovery=false` alone.

Formation defaults to join-only. Initial six-member formation or authorized full-cell reformation requires the bounded bootstrap override and external native recovery authorization; setting a Helm profile by itself must not create that authorization. No manifest is applied by the local contract test.
